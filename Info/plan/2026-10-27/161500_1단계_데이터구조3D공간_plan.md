## 1. 목적

탑차 적재함과 택배를 3D로 표현하기 위한 **데이터 구조**와 **3D 공간(씬)** 을 만든다. 사용자가 입력한 크기에 맞춰 적재함과 택배 직육면체가 화면에 생성되는 것까지가 이번 단계의 목표이다.

유전 알고리즘, 배치 계산, 적재 조건, 적합도, GA 파라미터 등은 **이번 단계 범위에 포함하지 않는다.**

---

## 2. 요청 범위 (1단계)

| 포함 | 내용 |
|---|---|
| O | 적재함 내부 크기(가로·세로·높이) 입력 및 `ContainerData` 관리 |
| O | 택배별 크기·수량 입력, 고유 ID 부여, `PackageData` 목록 생성 |
| O | Three.js 씬: 적재함(경계 표시), 택배 메시 생성 |
| O | 카메라·조명·궤도 조작 등 적재함 내부를 **볼 수 있는** 시점 |
| O | 입력 변경 시(또는 적용 버튼) 씬에 반영 |
| X | 택배 배치 위치 계산, 겹침·받침 검사 |
| X | 유전 알고리즘 및 적합도 |
| X | 최종 적재 결과·미적재 목록 표시(2단계 이후) |

### 2.1. 완료 기준 (DEV 초안 §7 1단계)

**입력한 크기로 적재함과 택배가 생성된다.**

- 적재함: 입력한 가로·세로·높이와 시각적 직육면체(또는 와이어프레임) 크기가 일치한다.
- 택배: 입력한 종류·수량만큼 ID가 부여되고, 각 택배의 크기에 맞는 직육면체가 생성된다.
- 1단계에서는 택배 **배치 최적화 없이** 미리보기용 배치(예: 바닥 격자·일렬 나열)만 허용한다. 위치는 “적재 결과”가 아니다.

## 4. 데이터 구성 (1단계에서 구현할 최소 항목)

DEV 초안 §3 중 이번 단계에 해당하는 항목만 구현한다.

| 데이터 | 주요 항목 | 1단계 역할 |
|---|---|---|
| 적재함 정보 | 가로, 세로, 높이 | `ContainerData` — 숫자 3개, 동일 단위 가정(단위 이름은 미정) |
| 택배 정보 | 고유 ID, 가로, 세로, 높이 | `PackageData` — 수량 입력 시 ID별 인스턴스 확장 |

1단계에서 **구현하지 않음**: `Individual`, `LoadingResult`(배치 결과), 알고리즘 설정, 적합도.

### 4.1. 구성 요소 (초안 §5 중 1단계)

| 이름 | 1단계 역할 |
|---|---|
| `ContainerData` | 적재함 크기 보관 |
| `PackageData` | 택배 ID·크기 보관 |
| `LoadingVisualizer` | Three.js로 적재함·택배 메시 생성·갱신 |

`PlacementSolver`, `PlacementValidator`, `FitnessEvaluator`, `GeneticAlgorithm` 등은 **파일·폴더 생성하지 않음**(후속 단계).

---

## 5. 3D·좌표 (1단계 최소 약속)

- 적재함 한 모서리를 원점, Three.js 기본 축(Y-up)을 사용한다.
- 크기 값은 **입력 숫자를 Three.js 월드 단위에 1:1**로 매핑한다. **길이 단위(mm/cm 등)는 미정** — 코드에는 `단위 미정` 주석 또는 상수 placeholder만 둔다.
- 적재함은 내부 공간이 보이도록 와이어프레임 또는 반투명 면 중 하나로 표시한다(구현 시 하나 선택).

---

## 6. UI (1단계)

- 적재함: 가로, 세로, 높이 입력 필드
- 택배: 크기(가로·세로·높이)와 **수량** — 수량 > 1이면 `ID-1`, `ID-2` … 형태로 개별 `PackageData` 생성(접두 ID 규칙은 구현 시 문서화)
- **「적용」 또는 입력 변경 반영**으로 씬 재구성
- GA 설정·실행 버튼은 **넣지 않음**

## 8. 확인 방법

| 확인 항목 | 방법 |
|---|---|
| 적재함 크기 | 입력값 변경 → 씬에서 변 변화 육안·치수 일치 |
| 택배 개수 | 수량 N → 메시 N개(또는 동일 ID 목록 N건) |
| 택배 크기 | 종류별 입력 크기와 박스 스케일 일치 |
| 시점 | 드래그 등으로 적재함 내부 확인 가능 |

자동 테스트는 1단계 **필수 아님**. 도입 시 `ContainerData`/`PackageData` 순수 로직만 Vitest 후보.
